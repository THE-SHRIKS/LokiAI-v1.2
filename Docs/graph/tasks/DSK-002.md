# Task Packet — `DSK-002 Typed preload bridge`

Packet status: `accepted`
Graph status: `ready` — dispatching
Starting revision: `1c465aa` (branch `LokiAI-v1.2`, pushed)

## 1. Objective

Replace `DSK-001`'s minimal placeholder preload with a real, narrow, typed
`contextBridge` API: an explicit allowlist of named, validated methods and an
event-subscription mechanism — never a generic `invoke`/raw-command bridge, per
`AGENTS.md`'s locked architecture. The methods this node defines will not yet
have a real backend (`RUN-002`'s local IPC exists, but no runtime-side handler
logic is wired to it yet by any accepted node) — every method must return an
honest "not yet available" error state rather than fabricate a response.
Grounding the exact method set in what `RUN-002`/`CTR-001` already define, not
inventing new ones speculatively.

## 2. Traceability

Requirements: `FR-UI-002`. Architecture: `Docs/ARCHITECTURE.md` ("Renderer-to-
main communication uses an explicit allowlisted preload API"). Parent:
`CTR-001`, `DSK-001`.

## 3. Dependencies and inputs

`depends_on`: `CTR-001`, `DSK-001` (both accepted). Type every exposed method's
request/response against `@lokiai/contracts` shapes where one exists; do not
invent a parallel type. `RUN-002` (local IPC) is dependency-ready but not
required by this node's packet — if `RUN-002` happens to be integrated by the
time this dispatches, the implementer may wire the preload's IPC calls to the
real named pipe; if not, stub the main-process side honestly (Section 1).
State explicitly in the handoff which case applied.

## 4. Required reading

`AGENTS.md`; `Docs/ARCHITECTURE.md` (preload/IPC section); `Docs/SECURITY.md`
(IPC validation requirements); `electron/main/index.cts`,
`electron/preload/index.cts` (existing `DSK-001` code — extend, don't replace
wholesale); `packages/contracts/src/*.ts` (relevant shapes, read-only).

## 5. Ownership

Writable: `electron/preload/**`, plus additive changes to `electron/main/**`
strictly limited to registering the new `ipcMain.handle`/`ipcMain.on` counterparts
the preload's new methods need (no unrelated main-process refactor). Do not
touch `LokiAI Desktop UI/src/**` (nothing consumes this bridge yet — that's a
`UI-*` node) or `packages/contracts/**`.

Forbidden: no generic `invoke(channel, ...args)` passthrough; no unvalidated
`ipcRenderer.on` forwarding raw event data without a schema check; no
filesystem/shell/serial/network access exposed to the renderer, ever.

## 6. Deliverables

1. A small, explicit set of typed preload methods (e.g., a health/status query,
   a device-list query, an event subscription for one class of runtime event)
   — bounded scope, not every future IPC surface; document in the handoff
   exactly which methods and why those specifically
2. Every method validates its arguments (types alone are not validation, per
   `AGENTS.md` rule 4) and validates/sanitizes what it returns to the renderer
3. Sender validation on the main-process side (confirm the IPC event's sender
   is the app's own known `webContents`, not blindly trusted)
4. Event-subscription mechanism with proper cleanup (unsubscribe removes the
   listener; no leak on repeated subscribe/unsubscribe)
5. Honest "not yet available" responses for methods with no real backend yet
   (Section 1) — never a fabricated success
6. Real tests: each method validates malformed input and rejects it; sender
   validation actually rejects a spoofed sender (test via direct unit test of
   the validation function, not requiring a full Electron harness if that's
   impractical — state which approach was used); subscribe/unsubscribe doesn't
   leak
7. Worker handoff at `Docs/graph/handoffs/DSK-002-1.md`
