## Objective

Implement a production local installation authority for the ADR-0002 local-only
milestone. Bind authority to the authenticated Windows installation identity and
local IPC session; persist only non-secret authority/session metadata; fail closed
for unknown principals and every cloud-required capability.

## Ownership

- Allowed: a new bounded Rust crate under `crates/loki-local-authority/`, the
  workspace manifest/lockfile, narrowly required local-authority migrations or
  contract additions, this packet, evidence, and handoff.
- Forbidden: renderer routes, cloud clients/contracts, device mutation, build
  executor, arbitrary shell/filesystem authority, and weakening IPC/DPAPI/ACL
  controls.

## Acceptance criteria

1. A local installation identity is distinct from account/workspace/cloud role
   identity and has a stable, validated ID.
2. Sessions are issued only after a caller-supplied Windows principal matches the
   configured installation owner; unknown/missing principals are denied.
3. Sessions have bounded expiry, explicit revocation, stable correlation IDs, and
   cannot be reused after revocation or expiry.
4. Capabilities are allowlisted and default-deny. Cloud-required capabilities
   return an explicit unavailable result and are never mapped to local authority.
5. Session metadata persists transactionally without storing bearer secrets or
   authority material in plaintext.
6. Restart, expiry, revocation, malformed/oversized identity, replay, and
   concurrent-revocation tests pass deterministically without sleeps.
