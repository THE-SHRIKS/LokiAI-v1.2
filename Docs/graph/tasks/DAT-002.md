## 1. Objective

Replace the accepted plaintext SQLite implementation with full SQLCipher
Community Edition protection for every existing runtime-owned bounded-context
database: core storage, monitoring/rules, and incidents/evidence. Provide one
reviewed Windows DPAPI-backed key lifecycle for desktop-user and gateway-service
identities, preserve data through a recoverable plaintext-to-encrypted
migration, and ensure wrong or missing key material never creates a healthy-
looking empty database.

## 6. Deliverables

1. A dependency-reviewed SQLCipher Community build configuration using the
   exact pinned `rusqlite` version. Record purpose, licence/attribution,
   maintenance/security posture, native-build impact, and removal path.
2. A runtime-owned Windows DPAPI secret abstraction with application-specific
   entropy, protected-key creation/read/replace, no secret logging, and
   identity-specific protection. Migrate the runtime IPC token to that same
   abstraction.
3. SQLCipher open/configuration helpers used by all three existing database
   contexts before any schema access, including WAL/journal/temp handling,
   busy timeout, integrity validation, and explicit wrong/missing-key errors.
4. Recoverable plaintext-to-encrypted migration and encrypted backup/rotation
   for all three contexts: preflight, encrypted backup, atomic replacement,
   reopen/integrity verification, durable recovery marker, and explicit
   interrupted-operation behavior.
5. Tests proving encrypted core, monitoring/rules, and incident/evidence
   stores; correct reopen/migration; wrong/missing key; key rotation; backup;
   WAL/journal/temp marker confidentiality; and desktop-user/service-identity
   separation where the CI/test identity permits it.
6. SQLCipher Community attribution/release-notice and worker handoff/evidence.

## 7. Acceptance criteria

- [ ] The repository builds against a pinned SQLCipher-capable library; no
      system SQLite is silently selected.
- [ ] All three database contexts and every generated sidecar/backup keep a
      known plaintext marker unavailable to an unkeyed SQLite open or byte scan.
- [ ] A correct key opens the expected existing data; wrong, missing, malformed,
      or identity-inaccessible key material gives a distinct error and leaves
      the original data in place.
- [ ] Plaintext-to-encrypted migration is crash/retry safe per durable recovery
      marker and never silently destroys or replaces the source data.
- [ ] Rotation and backup are integrity-checked, recoverable, and do not leave
      a plaintext destination.
- [ ] The runtime IPC token is no longer written as plaintext and uses the same
      OS-secret abstraction without exposing it through IPC, renderer, MCP, or logs.
- [ ] SQLCipher Community attribution is recorded for packaging/release.
- [ ] `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --
      -D warnings`, `cargo build --workspace`, `cargo test --workspace`, and
      `pnpm run verify` pass.
- [ ] An independent data-security review finds no unresolved blocking issue.
- [ ] No prohibited security or architecture boundary is weakened and no
      unrelated files change.

## 9. Risks and safety

- Risk level: `high`
- Failure modes: key loss; wrong Windows identity; corrupted/interrupted
  migration or rotation; plaintext sidecar/backup; SQLCipher build drift;
  transaction/integrity regression; accidental secret disclosure.
- Rollback/recovery: retain verified pre-migration backup and recovery marker;
  restore only through an explicit recovery action. Never downgrade or create a
  replacement database silently.
- Data/secret impact: sensitive local data and database keys. Keys remain
  OS-protected; logs/evidence contain no key value or protected blob.
- Executable/toolchain impact: SQLCipher is compiled from the pinned Rust
  dependency path; review source provenance and licence before acceptance.
- Cloud/offline impact: fully local; no cloud contract added.
- Device impact: none.
