## 4. Deliverables and acceptance criteria

1. Background host starts the IPC listener (`RUN-002`'s `Server`) alongside the
   existing health/logging from `RUN-001`.
2. Crash recovery: if the host process dies unexpectedly, a supervising
   mechanism (or documented OS-service-manager expectation — record which)
   restarts it; state that survived (via `DAT-001`) is intact after restart.
3. Desktop discovery: a documented, tested mechanism for the Electron main
   process (later `DSK-002`/`RUN-003` integration, not built here) to find the
   running host — e.g., a well-known named-pipe path or a discovery file with
   the actual listening address. Don't invent an undocumented ad-hoc protocol.
4. Truthful states: "host not running," "host starting," "host healthy," "host
   unreachable" are distinct and tested — no state silently defaults to healthy.
5. Real tests: startup with `RUN-002` IPC listener actually accepting a real
   connection; simulated crash-and-restart preserves `DAT-001` state; discovery
   mechanism actually locates a running host, and correctly reports "not
   running" when none exists (not a hang, not a false positive).
6. `cargo build/fmt/clippy/test --workspace` passes across all crates.
7. Worker handoff at `Docs/graph/handoffs/RUN-003-1.md`.
