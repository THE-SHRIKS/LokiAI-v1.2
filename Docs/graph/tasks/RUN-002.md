# Task Packet — `RUN-002 Local IPC and handshake`

Packet status: `accepted`
Graph status: `ready` — dispatching
Starting revision: `1c465aa` (branch `LokiAI-v1.2`, pushed)

## 1. Objective

New crate `crates/loki-ipc` (per `Docs/ARCHITECTURE.md` §11's target crate list —
a separate crate from `loki-runtime`, not a module bolted onto it): an
authenticated local named-pipe RPC transport with a version/capability
handshake, per-call deadlines, cancellation, and streaming support. This is the
transport `RUN-003`, `DSK-002`'s eventual real bridge, `JOB-001`, and others
build on. No business logic — pure transport + handshake + framing.

## 2. Traceability

Requirements: part of `FR-MCP-001`–`004` (transport layer), `NFR-COMP-001`
(compatibility matrix). Architecture: `Docs/ARCHITECTURE.md` (desktop-to-runtime
IPC: "authenticated, versioned local IPC contract... No generic `invoke`, raw
command, or arbitrary path bridge"). Parent: `RUN-001`, `CTR-001`.

## 3. Dependencies and inputs

`depends_on`: `RUN-001`, `CTR-001` (both accepted). `loki-ipc` depends on
`loki-runtime` as a library (path dependency within the Cargo workspace) for
whatever shared types `RUN-001` already established (logging/error conventions),
not the other way around — do not have `loki-runtime` depend on `loki-ipc` at
this stage (that wiring, if needed, is `RUN-003`'s job).

## 4. Required reading

`AGENTS.md`; `Docs/ARCHITECTURE.md` (IPC contract section); `crates/loki-runtime`
(read, for conventions to match — logging, error style, dependency-pinning
discipline).

## 5. Ownership

Writable: `crates/loki-ipc/**` (new); one `Cargo.toml` members line. Do not
touch `crates/loki-runtime/**` itself (read-only reference). Forbidden: no
authentication *policy* (RBAC etc. is `APR-001`) — this node does connection-
level authentication (proving the peer is a legitimate local process, e.g. via a
per-session token or named-pipe security descriptor restricting to the current
user), not user/role authorization; no actual business RPC methods yet, just the
transport + handshake + a minimal echo/ping method proving the pipe works
end-to-end.

## 6. Deliverables

1. `crates/loki-ipc/Cargo.toml`, dependency-justified (Windows named pipes via
   an appropriate crate — justify the specific choice; `tokio`'s
   `named_pipe` support if sufficient, avoiding a second async-IPC dependency
   duplicating what `RUN-001` already pulled in)
2. Named-pipe server (runtime side) and client (for tests / a future desktop-
   side consumer) with connection-level authentication restricting to the
   current Windows user session
3. Version/capability handshake: client and server exchange a protocol version
   and declared capabilities before any RPC call is accepted; a version
   mismatch is rejected with a clear error, not silently accepted
4. Per-call deadlines and cancellation (a call that exceeds its deadline is
   cancelled cleanly, not left hanging)
5. Streaming support (at least one direction — server-to-client streaming, the
   more commonly needed direction for telemetry/log tailing later nodes need)
6. Real tests: successful handshake; version-mismatch rejection; malformed
   frame handling (rejected, not a panic); deadline-exceeded cancellation
   actually cancels (not just times out the caller while the callee keeps
   running); backpressure behavior when a stream consumer is slow; a second
   connection attempt from a different user session is rejected (or: if this
   environment can't test cross-user-session behavior, say so plainly and test
   what's testable)
7. Worker handoff at `Docs/graph/handoffs/RUN-002-1.md`
