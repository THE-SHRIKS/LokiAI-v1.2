## 1. Objective

Bounded telemetry/log ingestion in `crates/loki-monitoring`: quality/freshness
tracking, buffering with an explicit bound (never unbounded memory growth),
storage via `DAT-001`'s repositories, and a subscription mechanism later nodes
(`MON-002`, UI) will consume. Device-neutral — no ESP32-specific assumptions
(`CON-001`'s connector-neutral vocabulary is what this ingests from, not a
specific connector).

## 2. Dependencies and ownership

`depends_on`: `CON-001`, `DAT-001` (both accepted). Writable:
`crates/loki-monitoring/**` (new) + one `Cargo.toml` members line. Do not touch
`crates/loki-connectors-sdk/**` or `crates/loki-storage/**` directly (new
migration file in `loki-storage/migrations/` if a new table is needed, same
single-writer rule as `JOB-001`'s packet).

## 3. Required reading

`AGENTS.md`; `Docs/ARCHITECTURE.md` (monitoring bounded context); `Docs/SPEC.md`
telemetry/freshness sections; `crates/loki-connectors-sdk/src/health.rs` (the
health-check shape this pipeline likely ingests).

## 4. Deliverables and acceptance criteria

1. Bounded ingestion buffer — a real, tested upper bound (dropping oldest or
   rejecting new, explicitly one or the other, never "grows forever").
2. Freshness/quality tracking: a stale data source is detectable, not silently
   treated as current.
3. Backpressure: a slow consumer does not crash or unboundedly memory-balloon
   the producer side.
4. Restart: telemetry state/buffering behaves sanely across a process restart
   (matches `DAT-001`'s restart-preserves-data discipline where storage is
   involved).
5. Real tests: buffer overflow behavior (drop policy proven, not assumed), a
   gap/loss scenario is detectable and reported honestly (not backfilled with
   fabricated data — `AGENTS.md` rule 1), backpressure doesn't deadlock or crash,
   restart scenario.
6. `cargo build/fmt/clippy/test --workspace` passes across all crates.
7. Worker handoff at `Docs/graph/handoffs/MON-001-1.md`.
