# Task Packet — `DSK-001 Secure Electron shell`

## 1. Objective

Run the existing, unmodified `LokiAI Desktop UI/` renderer inside a packaged,
security-hardened Electron shell: single-instance lock, truthful window/app
lifecycle (no fake "connected"/"ready" states), and the Electron security
baseline (`Docs/SECURITY.md`) — context isolation on, node integration off in the
renderer, sandboxed renderer, no remote-module, CSP set, permission requests
denied by default. This node does **not** add a preload bridge with real IPC
(that's `DSK-002`, after `CTR-001`) — a minimal empty/placeholder preload that
satisfies contextIsolation is fine, but no business logic in it yet. Do not move
`LokiAI Desktop UI/` to `apps/desktop/` — reference it at its current path.

## 5. Ownership

Writable paths: new `electron/main/**`, `electron/preload/**` at repo root (or
propose an equally-bounded alternative location in the handoff if there's a
strong reason — do not silently choose without recording why); root
`package.json` `dependencies`/`devDependencies` additions for Electron/Forge
tooling only (via `pnpm add`, exact versions, recorded with justification per
`AGENTS.md` rule 11); a new root script section for `electron:*`/packaging
commands. Do not edit `LokiAI Desktop UI/src/**` (zero renderer behavior
changes — this node only wraps it). Do not touch `packages/contracts` (`CTR-001`'s

Forbidden scope: no real preload API surface (empty/minimal only — real API is
`DSK-002`); no auto-update wiring (`PKG-002`); no tray/notification behavior
beyond what's needed for truthful lifecycle; no experimental Forge Vite plugin
(`TECH_STACK.md` explicitly rejects this — build renderer/main/preload
explicitly).

## 6. Deliverables

1. `electron/main/` — main process: creates the window, loads the built
   renderer, single-instance lock (`app.requestSingleInstanceLock()`), truthful
   ready/quit lifecycle, security hardening (CSP header, permission handler
   denying by default, disabled remote module, `webPreferences` with
   `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`)
2. `electron/preload/` — minimal preload script satisfying contextIsolation
   (can expose nothing or a trivial version string) — explicitly not a general
   `invoke`/arbitrary bridge (`AGENTS.md` locked-architecture rule)
3. Electron Forge config (packager + fuses per `TECH_STACK.md`) producing a
   Windows build
4. Root scripts: `electron:dev` (launch against the Vite dev server) and
   `electron:build`/`electron:package` (build renderer then package)
5. Security-relevant tests: verify `contextIsolation`/`nodeIntegration`/
   `sandbox` settings are actually what the code sets (a unit/config test
   reading the `webPreferences` object, not just eyeballing it)
6. A packaged smoke run: build, package, launch the packaged app, confirm the
   window opens and shows the real renderer (not a blank/error page), then quit
   — with real captured evidence (exit codes, a screenshot if the environment
   supports it), not narrated
7. Worker handoff at `Docs/graph/handoffs/DSK-001-1.md`

## 7. Acceptance criteria

- [ ] `pnpm run electron:dev` launches a window showing the real LokiAI UI
      against the Vite dev server
- [ ] Packaged build produces a runnable Windows executable
- [ ] Packaged app launches, shows the real UI, and quits cleanly — real
      evidence captured
- [ ] Second launch attempt while one instance is running is blocked
      (single-instance lock proven, not assumed)
- [ ] `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`
      verified by a test that inspects the actual `webPreferences`, not just
      code review
- [ ] No `remote` module, no generic IPC `invoke` bridge exposed
- [ ] Zero changes to `LokiAI Desktop UI/src/**`
- [ ] `pnpm run verify` (root) still passes
- [ ] Failure/unavailable behavior explicit (e.g., renderer build missing →
      truthful error, not a blank silent window)
