# Task Packet — `MCP-001 MCP server foundation`

Packet status: `accepted`
Graph status: `ready` — dispatching
Starting revision: `1c465aa` (branch `LokiAI-v1.2`, pushed)

## 1. Objective

New workspace package `services/mcp-server`: a provider-neutral, standalone
stdio MCP server using the official TypeScript SDK, speaking the `2026-07-28`
MCP protocol revision (with per-request metadata / optional discovery) plus one
bounded previous-version edge adapter, per `Docs/MCP_SPEC.md` and
`Docs/TECH_STACK.md`. Schemas, structured errors, diagnostics. No transport-
session authority (no auth/session state of its own — that is layered on by
later nodes once `AUTH-001`/`RUN-002` exist). No tools/resources yet
(`MCP-002`) — this node is the server shell: initialize handshake, capability
negotiation, error handling, and the version/discovery edge behavior.

## 2. Traceability

Requirements: `FR-MCP-001`. Architecture: `Docs/MCP_SPEC.md` (full),
`Docs/TECH_STACK.md` (MCP row — official TS SDK, own Node runtime not Electron's
embedded one). Parent: `FND-002`, `CTR-001`.

## 3. Dependencies and inputs

`depends_on`: `FND-002`, `CTR-001` (both accepted). Use `@lokiai/contracts`'

(`"@lokiai/contracts": "workspace:*"`), not a reimplementation.

## 4. Required reading

`AGENTS.md`; `Docs/MCP_SPEC.md` (full); `Docs/TECH_STACK.md` (MCP row);

## 5. Ownership

Writable: `services/mcp-server/**` (new). Forbidden: no concrete tools/resources

tools); no auth/session logic; no device/connector access of any kind.

## 6. Deliverables

1. `services/mcp-server/package.json` — new workspace member, real exact
   registry-checked versions for the official MCP TypeScript SDK and any
   stdio-transport dependency
2. Server bootstrap: stdio transport, `initialize` handshake, capability
   negotiation for MCP `2026-07-28`, plus the one bounded previous-version edge
   adapter `Docs/MCP_SPEC.md` requires for the certified clients
3. Structured error responses (using `@lokiai/contracts`' error shapes where
   applicable) and structured diagnostics/logging
4. Real tests: successful initialize on the current protocol version; the
   previous-version edge adapter path; a malformed/unsupported client-metadata
   request handled with a clear protocol-conformant error, not a crash; the
   server never advertises a tool/resource capability it doesn't actually have
