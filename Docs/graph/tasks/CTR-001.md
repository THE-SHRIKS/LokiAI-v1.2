## 1. Objective

Define versioned, shared, cross-language contracts — IDs, envelopes, errors, state
enums, IPC DTOs, MCP schema shapes, and connector capability schemas — as the
single source of truth both the TypeScript side (renderer/preload/MCP server) and
the Rust side (runtime/connectors) validate against. This node produces the
contract *definitions and TypeScript types/validators*; a Rust codegen/crate
consumer is a fast-follow once `RUN-001`'s Cargo crate exists, not blocking here.

## 6. Deliverables

1. `packages/contracts/package.json` — new workspace member, name
   `@lokiai/contracts`, `private: true`, exact versions matching root pins
2. Versioned ID types (device, workspace, run, job, deployment, incident, etc. —
   base on `Docs/SPEC.md` entity list), branded/nominal where useful to prevent
   ID-type confusion
3. Envelope/error shape shared by IPC and MCP responses (success/error
   discriminated union, correlation ID, timestamp)
4. State enums matching `Docs/SPEC.md` state machines (connection, job, incident,
   deployment, onboarding states — as defined there, not invented)
5. Connector capability schema shapes per `Docs/CONNECTOR_SPEC.md`
6. Runtime validators (not just compile-time types) for every exported shape —
   types alone are not validation per `AGENTS.md` rule 4
7. Unit tests proving valid inputs pass and malformed inputs are rejected
   (missing field, wrong type, unknown enum value, oversized payload)
8. `packages/contracts/README.md` — what this package is, versioning policy,
   how consumers import it
9. Worker handoff at `Docs/graph/handoffs/CTR-001-1.md`
