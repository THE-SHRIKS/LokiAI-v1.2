# Task Packet — `DAT-001 SQLite and migrations`

Packet status: `accepted`
Graph status: `ready` — dispatching
Starting revision: `1c465aa` (branch `LokiAI-v1.2`, pushed)

## 1. Objective

New crate `crates/loki-storage`: runtime-owned SQLite schema, versioned
migrations, repository pattern over the entities `packages/contracts` (`CTR-001`)
defines, an outbox/inbox table pair for future cloud sync (`CLD-002`), and
integrity/backup primitives. Plaintext SQLite for now — full-database encryption
is `DAT-002` (blocked on `OQ-007`); this node must not invent an encryption
scheme to fill that gap, just leave the key/cipher boundary as an explicit,
swappable seam.

## 2. Traceability

Requirements: `NFR-DATA-001`. Architecture: `Docs/ARCHITECTURE.md` (persistence
process boundary — runtime-owned, never the renderer). Parent: `FND-002`, `CTR-001`.

## 3. Dependencies and inputs

`depends_on`: `FND-002`, `CTR-001` (both accepted). Consumes `@lokiai/contracts`'
ID/state types where a schema needs to store one (do not redefine a parallel ID
type in Rust — `CTR-001`'s handoff explicitly warns against a divergent Rust copy;
until a Rust contracts crate/codegen exists, use the Rust newtype/struct shape
that mirrors the TS contract's cited `Docs/SPEC.md` section, and cite the same
section in a doc comment, not the TS file).

## 4. Required reading

`AGENTS.md`; `Docs/ARCHITECTURE.md`; `Docs/SPEC.md` (entity definitions);
`packages/contracts/README.md` and relevant `src/*.ts` (for the ID/state shapes
to mirror, read-only — do not edit that package); `crates/loki-runtime/Cargo.toml`
(for dependency-pinning conventions to match).

## 5. Ownership

Writable: `crates/loki-storage/**` (new); one line in root `Cargo.toml`'s
`members` array appending this crate (mechanical only, same discipline as
`RUN-001`'s packet — do not otherwise touch that file). Do not touch
`crates/loki-runtime/**`, `packages/contracts/**`, `electron/**`.

Forbidden: no encryption (that is `DAT-002`); no IPC exposure (`RUN-002`
consumes this crate as a library later, not the other way around); no outbox
delivery/transport logic, just the durable table structure and repository
read/write API.

## 6. Deliverables

1. `crates/loki-storage/Cargo.toml` — dependency-justified per `AGENTS.md` rule
   11, matching `RUN-001`'s exact-version-pinning convention (real crates.io
   versions, `cargo build` is itself the proof they exist)
2. SQLite schema + versioned migration runner (embed migrations as SQL files or
   inline, applied idempotently at startup)
3. Repository pattern for at least: device registry, job records, and the
   outbox/inbox pair (bounded scope — do not build every entity's repository
   speculatively; these three exercise the pattern for later nodes to extend)
4. Integrity check (e.g., `PRAGMA integrity_check`) and a backup primitive
   (file-level copy with a documented consistency guarantee — WAL checkpoint
   before copy, or equivalent)
5. Real tests: migration applies cleanly on empty DB; migration is idempotent
   (running twice doesn't fail/duplicate); a corrupted DB file is detected, not
   silently accepted; a restart with existing data preserves it; a transaction
   that fails mid-way rolls back completely (no partial write observable)
6. Worker handoff at `Docs/graph/handoffs/DAT-001-1.md`
