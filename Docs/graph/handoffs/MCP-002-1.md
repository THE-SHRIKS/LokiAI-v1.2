## 7. Decisions and assumptions

1. **The real IPC/registry data path genuinely does not exist yet, and this
   node did not fabricate one.** Verified directly, not assumed:
   - `RUN-003` (background host lifecycle — the process that would embed
     `crates/loki-connector-registry` and own a `crates/loki-ipc` server
     endpoint) is `proposed`/in-progress per `Docs/graph/TASK_GRAPH.md`
     Section 4, not `accepted`.
   - `crates/loki-ipc` (read, not modified) defines transport + handshake +
     deadline/cancellation/streaming + one echo/ping method, per its own
     task packet's explicit scope ("no business logic ... just the
     transport + handshake + a minimal echo/ping method"). It has no
     device/health RPC method.
   - `crates/loki-connector-registry` (read, not modified) has **no**
     `loki-ipc` dependency at all — its own worker handoff (`Docs/graph/
     handoffs/CON-002-1.md`, Section 7 decision 2) documents this as a
     deliberate choice, not an oversight.
   - `crates/loki-ipc`'s client (`src/client.rs`) is a Rust API; no
     Node/TypeScript client for its wire protocol exists anywhere in this
     repository.
   - Even setting IPC aside, `loki-connector-registry`'s own public API
     (`registry.rs`) models *registered connector instances*
     (`RegisteredConnectorSummary`, keyed by `ConnectorId`), not the
     persisted domain `Device` entity `Docs/SPEC.md` 3.3 defines — there is
     currently no "device list" concept on the Rust side to even relay,
     independent of the IPC gap.

   Given all of this, I read the task packet's Section 3 ("if no runtime
   process/consumer exists yet to answer such a call, an honestly-reported
   `runtime_unavailable` result — the same discipline DSK-002's IPC bridge
   already established") as the explicitly pre-authorized resolution for
   exactly this situation, not grounds for `NEEDS_REPLAN`. The Section 12
   `NEEDS_REPLAN` stop condition is reserved for when this node's
   acceptance criteria become "unverifiable except via a stub" — that is
   not the case here: pagination, size-bounding, scope-filtering, and the
   honest-unavailable/honest-not-found distinctions are all real,
   independently verified behavior (85 passing tests, including 9 full
   real-protocol integration tests against the actual production factory),
   not narrated. Only the final data-fetch step is (honestly) a stub.

2. **Discovered mid-implementation: the official MCP SDK reports a tool's
   own input-schema validation failure as an `isError: true`
   `CallToolResult`, not a rejected JSON-RPC protocol error.** My first
   draft of `tests/toolsIntegration.test.ts` assumed (incorrectly, before
   running it) that a malformed `device_id`/out-of-range `limit` would
   reject with `ProtocolError`, matching `tests/malformedRequests.test.ts`'s
   *transport-level* malformed-request pattern. Running the tests
   surfaced the real behavior: `McpServer`'s `tools/call` handler catches
   the schema validation's thrown error internally and returns
   `createToolError(...)` — a normal JSON-RPC success response wrapping
   `isError: true`. I corrected the tests to assert the real behavior
   (`result.isError === true` with an "Invalid arguments" message) rather
   than loosening the assertion to force a false pass; true protocol-level
   errors (unknown tool name, malformed envelope) still reject with
   `ProtocolError` and are asserted as such.

3. **Pagination and scope-filtering are combined at the `DeviceDataSource`
   boundary, not layered by the tool handler after the fact.**
   `ListDevicesParams.isDeviceAuthorized` is passed *into* the data source
   call so a real backend can filter before counting/paginating — a page is
   always "N authorized devices," never "N raw devices, some later dropped
   for being unauthorized." This is my own design choice (not dictated by
   the packet); documented in `src/devices/types.ts`'s `ListDevicesParams`
   doc comment and flagged for reviewer attention in Section 8.

4. **`AggregatedHealthStatus` and `Freshness` are local wire vocabularies,
   not additions to `@lokiai/contracts`.** `packages/contracts/**` is
   outside this node's writable scope. Both mirror real upstream sources
   (a Rust enum; `packages/contracts/src/mcp.ts`'s own explicit deferral) —
   see Section 5.
