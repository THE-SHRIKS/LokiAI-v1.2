## 2. What I found and fixed

1. **Broken/placeholder `pnpm-workspace.yaml` entry.** `esbuild` genuinely is a
   direct dependency (`scripts/build.ts` bundles the server, inlining
   `@lokiai/contracts`, so it ships as a self-contained launcher per
   `TECH_STACK.md` rather than depending on Electron's embedded Node) and its
   postinstall script is the standard mechanism for downloading the correct
   platform-specific native binary — not a supply-chain concern. Fixed the
   config properly: removed the invented `allowBuilds` key (not a real pnpm
   option) and the placeholder value, added `esbuild` to the existing
   `onlyBuiltDependencies` array with the same reviewed-and-documented
   precedent `DSK-001` already established for `@electron/node-gyp`.
2. **One real type error**: a test passed a plain `string` where CTR-001's
   branded `CorrelationId` type was expected. Fixed by constructing it through
   `CorrelationIdSchema.parse(...)`, the correct pattern.
3. **Two tests asserted the wrong error class**: both expected
   `instanceof SdkError` for a protocol-version rejection, but the real SDK
   throws the more specific sibling class `ProtocolError` (`SdkError` and
   `ProtocolError` both extend `Error` directly — no inheritance relationship
   between them; confirmed by reading the SDK's own `.d.ts`). The underlying
   *behavior* was already correct (a well-formed error with the right
   code/data); only the test's expected class was wrong. Fixed both.
4. **10 real ESLint findings** once the root config actually covered this new
   package (see Section 7 for the pre-existing gap that initially hid these):
   6 legitimate `require-await` false positives (a test-helper callback type
   requires `Promise<T>`, so `async` is structurally necessary even where the
   body has no `await` — fixed with narrow, individually-justified inline
   disables, not a blanket rule change), 3 `no-unnecessary-type-assertion` /
   `no-unsafe-assignment` findings on `JSON.parse()` results (removed a
   redundant `!` non-null assertion — this repo doesn't have
   `noUncheckedIndexedAccess`, so it was genuinely unnecessary — and added
   narrow, justified suppressions for the unsafe-assignment, since these
   tests parse their own known-shape fixture output, not untrusted input that
   would warrant a real runtime validator), and 1 `unbound-method` finding
   fixed properly with `.bind()` rather than suppressed.
