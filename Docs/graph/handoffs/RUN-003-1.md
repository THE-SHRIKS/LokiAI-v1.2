  is exactly the same composed-host process a direct, unsupervised
  invocation would be. This keeps there being exactly one code path that
  actually starts the host.
- **Windows-only gate for the whole `host` module** (`#[cfg(windows)] pub
  mod host;` in `lib.rs`, `#[cfg(windows)]`/`#[cfg(not(windows))]` pairs in
  `app.rs`), matching `loki-ipc`'s own `compile_error!`-enforced boundary
  and preserving the property (already documented in this crate's
  `Cargo.toml`) that `cargo check -p loki-runtime` alone still compiles for
  a non-Windows contributor, even though `cargo build/test --workspace`
  itself already requires Windows (`loki-ipc` is an unconditional workspace
  member with no non-Windows fallback of its own).
- **Test-only production-path change**: `ctrl_break_triggers_graceful_shutdown`
  (a pre-existing `RUN-001` test) needed its wait condition changed — it now
  waits for `"ipc listener bound and serving"` instead of `"loki-runtime
  starting"`, plus a 200ms buffer — because the new synchronous host-startup
  work (`ComposedHost::open`: real SQLite migration + real named-pipe bind)
  now sits between those two log lines, and sending `CTRL_BREAK` before the
  OS console-control handlers are actually installed terminates the process
  outright (`STATUS_CONTROL_C_EXIT`) instead of triggering graceful
  shutdown. This is a test-harness timing fix, not a change to
  `RUN-001`'s shutdown-signal-handling logic itself (`src/shutdown.rs` is
  untouched).

  wait for a detectable restart" to add significant test flakiness/runtime
