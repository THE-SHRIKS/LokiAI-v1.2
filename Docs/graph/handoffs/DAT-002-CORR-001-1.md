## 1. Outcome

The Windows storage lifecycle now fails closed for missing, truncated, wrong-key,
malformed, inaccessible-identity, active-maintenance, and retained-recovery
states. Migration and rotation retain a verified encrypted database/key recovery
generation, use cross-process maintenance ownership plus a non-cooperative
Windows database write fence, and deterministically recover a matching pair
after injected post-key-promotion failure. DPAPI persistence is purpose-bound,
ACL-protected, and SQLCipher configuration/integrity is verified; protected IPC
token startup always scrubs and removes a surviving legacy plaintext token.
Independent second-identity/VM execution remains mandatory before DAT-002 can be
accepted.

## 7. Decisions and assumptions

- A durable operation journal and a live OS-owned maintenance lease are separate mechanisms: the journal supports crash recovery while `LockFileEx` proves liveness.
- Any lifecycle artifact with both live files absent blocks first-use creation with `RecoveryRequired`; recovery state is never silently replaced with empty data.
- SQLCipher online backup is used for encrypted-to-encrypted snapshots; plaintext migration uses `sqlcipher_export` from a URI-read-only main database while the Windows write fence prevents concurrent mutation.
- Current-identity tests are implementation evidence only and are not substituted for the required second-identity matrix.
